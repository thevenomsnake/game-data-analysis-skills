# Excel 日报周报可视化

当前版本承接“失控进化数据周报”的完整流程。导入约定格式的 Excel 后，页面生成七个数据模块；工作状态会保存为项目内的本地草稿，也可以导出为不依赖原 Excel 的固定版 HTML。

## 启动方式

双击 `start.cmd`，然后在 Chrome 或 Edge 中打开：

```text
http://127.0.0.1:8765
```

也可以在当前目录运行：

```powershell
py -3 server.py
```

不要直接双击 `index.html` 开始正式编辑。通过 `file://` 打开时仍能导入和导出，但页面无法把草稿写入项目目录，并会明确显示未保存状态。

## 使用方式

1. 点击“导入 Excel”，选择 `.xlsx` 或 `.xls` 文件。文件上限为 50 MB。
2. 检查报告周期、标题、口径说明和核心结论，按需要修改并保存。
3. 七个模块全部载入后，点击“固定并导出”。

Excel 导入成功，以及标题、周期、口径说明或核心结论保存后，完整工作状态都会写入 `.local/report-state.json`。关闭页面或重启本地服务后，再次打开会自动恢复；需要清空草稿时，删除这个文件即可。

Excel 内容在浏览器中解析。草稿只发送给 `127.0.0.1` 上的本地服务，不会上传到外部网络；`.local/` 已被 Git 忽略。

## 输入边界

模板按固定工作表名称和表头读取数据。当前声明的工作表分为七组：

| 模块 | 模板读取的工作表数 |
| --- | ---: |
| 来量情况 | 4 |
| 漏斗转化 | 5 |
| 活跃情况 | 3 |
| 留存 | 7 |
| 商业化 | 21 |
| 模式游玩 | 4 |
| 关键游戏行为 | 8 |

工作簿中的全部工作表都会先进入“工作簿检查”区，页面展示范围、预览、候选表头和读取诊断。用户可以调整表头行、数据起始行及字段角色，配置会随本地草稿保存。额外工作表不会静默消失；只有匹配周报模板的工作表会进入七个固定模块，缺失或表头不匹配时页面会指出首个无法读取的位置。

## 实现边界

`index.html` 和 `workbook-inspector.js` 共同组成前端，基于一个虚构的周报模板；`server.py` 使用 Python 标准库提供静态页面和草稿读写，不引入额外依赖。页面使用 SheetJS 读取 Excel、ECharts 渲染图表，并在导出时克隆当前页面，把固定版所需的数据以 JSON 嵌入 HTML。

当前只落地周报模板。日报模板尚未建立；后续增加日报时，应复用现有导入、草稿和固定导出机制，不改动这份周报的数据契约。
